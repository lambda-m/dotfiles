dotfiles manual

GNU Stow + git, shared by the Macs and the Linux VMs. Repo: ~/dotfiles, branch setup.

TL;DR How it fits together dots upd New or existing machine Packages When something is off
Daily use 
dots            # am I in sync?  (uncommitted / unpushed / unpulled)
dots sync       # commit everything, pull --rebase, push, restow if needed
upd             # what is outdated? (brew, npm -g, apt, dnf, pacman)
upd upgrade     # per manager: show list, ask y/N, upgrade

Every new terminal or ssh login prints at most two lines when action is needed:

dotfiles: 2 uncommitted, 1 unpulled  ->  dots sync
updates: brew 3 (git, tmux, node), npm 1 (ccstatusline)  ->  upd

Nothing here ever changes anything without you typing the command or answering y.

How it fits together

Each top-level directory is a Stow package that mirrors $HOME. ./bootstrap.sh symlinks the packages into $HOME, so editing ~/.zshrc edits the repo. Stow only folds directories it fully owns; the shared ones (~/.config, ~/.local/{bin,share,state}) are created as real directories first, so installers never write into the repo.

Shell load order

zsh : ~/.zshrc -> ~/.profile -> ~/.local/profile.d/*.sh -> ~/.zshrc.local bash : ~/.profile (login) -> ~/.local/profile.d/*.sh -> ~/.bashrc -> ~/.bashrc.local sh : ~/.profile -> ~/.local/profile.d/*.sh -> ~/.profile.local

Everything cross-shell lives in profile.d and must stay POSIX. Only completion and prompt code go in .zshrc / .bashrc.

profile.d fileDoes
00-path.shPATH with path_prepend / path_append (idempotent, skip missing dirs). User dirs win over Homebrew. Installer PATH lines go here, never in an rc file.
10-env.shEDITOR = emacs-cli when Emacs is installed, else vim, else vi. PAGER, Python, MPS fallback.
20-functions.shta, mkcd (see shell package).
30-alias.shemacs/emacs-gui via emacsclient (only if installed), ll la l, zsh-only noglob ytgrab.
50-emacs-daemon.shStarts the Emacs daemon in the background if installed and not running.
60-dots-nudge.shThe dotfiles: login line.
70-upd-nudge.shThe updates: login line.

Machine-local, never committed

~/.profile.local, ~/.bashrc.local, ~/.zshrc.local are sourced last if they exist. State lives outside the repo: ~/.local/state/emacs, ~/.local/state/dots, ~/.local/state/upd.

dots: keep the clones in sync

Script: shell/.local/bin/dots. Finds the repo through the ~/.profile symlink, so the clone can live anywhere (DOTFILES= overrides).

CommandDoes
dotsStatus: branch, uncommitted files, commits unpushed / unpulled, incoming commit list. No network.
dots sync [msg]git add -A + commit (message defaults to hostname and date), pull --rebase --autostash, push. If new commits came in, reruns bootstrap.sh so new files get linked.
dots fetchFetch, then status.
dots stow [pkg..]Run bootstrap.sh (restow).
dots git <args>Any git command inside the repo, from anywhere.
dots dirRepo path: cd "$(dots dir)".

The login nudge fetches from origin in the background at most once a day, with ssh BatchMode so it never prompts or hangs. If a rebase conflicts: fix the file, dots git rebase --continue, dots sync.

upd: what is outdated

Script: shell/.local/bin/upd. Detects brew, npm globals (excluding npm itself, which follows node), apt, dnf, pacman. Results are cached in ~/.local/state/upd.

CommandDoes
updCached results per manager and the age of the cache.
upd checkRefresh now: brew update + outdated, npm outdated -g, apt simulation, and so on.
upd upgrade [mgr]Per manager: show the list, ask y/N, upgrade. Linux managers use sudo at that point only.

The login nudge starts a detached refresh when the cache is older than a day; the first login after that shows nothing yet, the next one is accurate. On Debian/Ubuntu the apt result is as fresh as the system's own daily apt update timer.

New or existing machine

# new machine
git clone git@github.com:lambda-m/dotfiles.git ~/dotfiles
cd ~/dotfiles && ./bootstrap.sh          # then open a new shell

# machine that already has the repo but not dots yet
cd ~/dotfiles && git pull && ./bootstrap.sh

# from then on, everywhere
dots sync

bootstrap.sh creates the shared dirs, repairs a folded ~/.local, removes an empty ~/.emacs.d, sets pull.rebase and push.autoSetupRemote, and stows core shell bash zsh tmux emacs plus ghostty ccstatusline on macOS. Pass package names to stow only those. If git pull refuses because of local edits, git stash first and git stash drop afterwards (the usual culprit is a tool rewriting its own config file).

Packages: what is special in each

core

~/.profile: the shared entry point that sources profile.d and, in bash, .bashrc. Rarely touched.

shell

~/.local/profile.d (table above) and ~/.local/bin:

  • dots, upd: this manual.
  • ta [name]: tmux attach-or-create, default session main; switches client when already inside tmux. Tab-completes session names.
  • mkcd dir: mkdir and cd.
  • ytgrab: YouTube downloader with playlist symlinks (bash, needs yt-dlp).
  • sshconfig-open host + SSHConfigOpener.app: open an ssh host in a new Ghostty window (macOS).

bash, zsh

Thin: bash has ta completion; zsh has the virtualenv-aware prompt, compinit with ~/.zsh/completion (custom _make), and ta completion. Both end by sourcing their .local file.

tmux

~/.config/tmux/tmux.conf plus a ~/.tmux.conf shim for old tmux. Nord theme, mouse on, 1-based indexes, splits on prefix | and prefix -. extended-keys on so Shift+Enter reaches Claude Code. Reload: tmux source-file ~/.config/tmux/tmux.conf. tmux wiki

emacs

Config in ~/.config/emacs, all state in ~/.local/state/emacs (elpa, custom.el, caches). Runs as a daemon; emacs and emacs-cli are terminal clients, emacs-gui opens a frame. Packages via use-package from MELPA (nord-theme, neotree, no-littering, xclip, auto-package-update: asks weekly in the first frame).

  • F8 neotree, M+arrows move between windows, Esc quit.
  • C-c y YAML to JSON, C-c j JSON to YAML (needs yq).

Restart the daemon after config changes: emacsclient -e '(kill-emacs)', then open emacs.

ghostty (macOS)

Nord, IosevkaTerm Nerd Font 16, left Option as Alt, huge scrollback. Cmd+` toggles the quick terminal from anywhere. config reference

ccstatusline (macOS)

Claude Code status line: model, session and weekly usage, context %, git branch and changes, Nord colours. Installed as a global npm package, so upd upgrade npm updates it. It rewrites its own settings.json on version bumps; just dots sync when that shows up. Interactive editor: run ccstatusline in a terminal. github.com/sirmalloc/ccstatusline

sublime

User settings only: Package Control list, Markdown + MarkdownPreview, LSP-yaml, Terminus colour scheme. Stow it only on machines with Sublime Text (./bootstrap.sh sublime).

not stowed

wallpapers/ (old computer photos), README.md, this manual, .stowrc (target $HOME, ignore .DS_Store).

When something is off

SymptomCause and fix
Hundreds of MB untracked under shell/.local/share ~/.local got folded into a symlink by a bare stow shell. Run ./bootstrap.sh; it moves the foreign files to the real ~/.local and restows.
Emacs ignores the config A ~/.emacs.d or ~/.emacs exists and shadows ~/.config/emacs. bootstrap removes an empty one; otherwise move it away and restart the daemon.
Shift+Enter submits in Claude Code You are in a tmux started before the extended-keys setting. Detach and ta again.
Installer appended lines to ~/.zshrc That edited the repo. Move the PATH line into 00-path.sh with path_append, delete it from the rc file, dots sync.
dots sync says pull failed Rebase conflict. dots git status, fix, dots git rebase --continue, dots sync. For ccstatusline's settings.json just take either side.
dot: can't open sync That is Graphviz. The helper is called dots.
Login shows no updates: line although things are outdated Cache older than a day, refresh running in the background. Next shell, or upd check.
