dotfiles manual

GNU Stow and git, shared by three Macs and the Linux VMs. The repo is ~/dotfiles, branch setup. This page is a map; the repo is the source of truth.

Daily use

dots            # am I in sync? (uncommitted, unpushed, unpulled)
dots sync       # commit everything, pull --rebase, push, restow if needed
upd             # what is outdated? (brew, npm -g, apt, dnf, pacman)
upd upgrade     # per manager: show the list, ask y/N, upgrade

Every new terminal or ssh login prints at most two lines, and only when something needs attention:

dotfiles: 2 uncommitted, 1 unpulled  ->  dots sync
updates: brew 3 (git, tmux, node), npm 1 (ccstatusline)  ->  upd

Nothing changes anything until you type the command or answer y.

How it fits together

Each top-level directory is a Stow package that mirrors $HOME. Running ./bootstrap.sh symlinks the packages into $HOME, so editing ~/.zshrc edits the repo. Stow folds only directories it fully owns. The shared ones, ~/.config and ~/.local/{bin,share,state}, are created as real directories first, so installers never write into the repo.

Shell load order

zsh : ~/.zshrc -> ~/.profile -> profile.d/*.sh -> ~/.zshrc.local bash : ~/.profile (login) -> profile.d/*.sh -> ~/.bashrc -> ~/.bashrc.local sh : ~/.profile -> profile.d/*.sh -> ~/.profile.local

Everything cross-shell lives in ~/.local/profile.d and must stay POSIX. Only completion and prompt code go in .zshrc and .bashrc.

profile.d fileWhat it does
00-path.shBuilds PATH with path_prepend and path_append, which are idempotent and skip missing directories. User directories win over Homebrew. Installer PATH lines go here, never in an rc file.
10-env.shSets EDITOR to emacs-cli when Emacs is installed, else vim, else vi. Also PAGER, Python, the MPS fallback, and the brew bundle variables.
20-functions.shta and mkcd. See the shell package.
30-alias.shemacs and emacs-gui through emacsclient, only if installed; ll, la, l; zsh-only noglob ytgrab.
50-emacs-daemon.shStarts the Emacs daemon in the background if it's installed and not running.
60-dots-nudge.shPrints the dotfiles: login line.
70-upd-nudge.shPrints the updates: login line.

Machine-local, never committed

~/.profile.local, ~/.bashrc.local, and ~/.zshrc.local are sourced last if they exist. State lives outside the repo in ~/.local/state/emacs, ~/.local/state/dots, and ~/.local/state/upd.

dots: keep the clones in sync

Script: shell/.local/bin/dots. It finds the repo through the ~/.profile symlink, so the clone can live anywhere. Set DOTFILES= to override.

CommandWhat it does
dotsStatus: branch, uncommitted files, commits unpushed and unpulled, and the incoming commit list. No network.
dots sync [msg]Runs git add -A and commits (the message defaults to hostname and date), then pull --rebase --autostash, then push. If new commits came in, reruns bootstrap.sh so new files get linked.
dots fetchFetches, then shows status.
dots stow [pkg..]Runs bootstrap.sh (restow).
dots git <args>Any git command inside the repo, from anywhere.
dots dirPrints the repo path: cd "$(dots dir)".

The login nudge fetches from origin in the background at most once a day, with ssh BatchMode so it never prompts or hangs. If a rebase conflicts, fix the file, then run dots git rebase --continue and dots sync.

upd: what is outdated

Script: shell/.local/bin/upd. It detects brew, npm globals (excluding npm itself, which follows node), apt, dnf, and pacman. Results are cached in ~/.local/state/upd.

CommandWhat it does
updShows the cached results per manager and the age of the cache.
upd checkRefreshes now: brew update and outdated, npm outdated -g, an apt simulation, and so on.
upd upgrade [mgr]Per manager: shows the list, asks y/N, upgrades. Linux managers use sudo at that point only.

The login nudge starts a detached refresh when the cache is older than a day. The first login after that shows nothing yet; the next one is accurate. On Debian and Ubuntu the apt result is as fresh as the system's own daily apt update timer.

brew: what should be installed

Where upd asks what is outdated, brew/ answers what should be installed on each Mac. It's a set of layered Brewfiles that you run by hand. There's no stow package and no login hook, and bootstrap.sh ignores it.

The files

FileContents
Brewfile.commonAll three Macs: every formula, the universal casks, VS Code extensions.
Brewfile.maxbookproCommon plus everything else. This one is the superset.
Brewfile.macminiCommon plus office extras.
Brewfile.airCommon plus daily-driver extras.
MANUAL.mdThe handful of things Homebrew can't install.

Brewfiles are Ruby. Each machine file loads the common one with instance_eval, which is why a single file covers both layers. Never point a command at Brewfile.common directly: it has no machine entries, so cleanup would offer to remove them all.

Which file this machine uses

In every shell, 10-env.sh derives the file name from the hostname:

uname -n | cut -d. -f1 | tr '[:upper:]' '[:lower:]'

That is the first label of the hostname, lowercased. Hyphens and digits stay. If brew/Brewfile.NAME exists, the script exports it as HOMEBREW_BUNDLE_FILE, and brew bundle needs no --file flag. If no file matches, the variable stays unset and brew looks for a Brewfile in the current directory.

uname -nDerived nameResult
MaxBookPromaxbookproBrewfile.maxbookpro
MacMini.localmacminiBrewfile.macmini
Maartens-Mac-mini.localmaartens-mac-miniNo file. Nothing is set.

If a Mac's name doesn't match a file, either rename the file or rename the Mac. To rename the Mac, set all three names so that Finder, Bonjour, and ssh agree:

sudo scutil --set ComputerName MacMini
sudo scutil --set HostName MacMini
sudo scutil --set LocalHostName MacMini

Then open a new shell and confirm with echo $HOMEBREW_BUNDLE_FILE.

Commands

CommandWhat it does
brew bundle checkLists what is written down but missing.
brew bundle installInstalls what is missing. Never removes anything.
brew bundle cleanupPrints what is installed but unlisted, asks y/n, then uninstalls. This is not a dry run; answer n to only look. --force skips the question.
brew bundle add --cask X --installInstalls a cask and writes it into this machine's file in one step. Omit --cask for formulae. Add --file=brew/Brewfile.common if all three Macs should have it.

To survey another Mac, look before you install, or you install forty things before seeing what was already there:

cd ~/dotfiles && dots sync
brew bundle cleanup     # 1. what is here that is not written down? (answer n)
brew bundle check       # 2. what is written down but missing?
brew bundle add --cask X                                # 3. keepers, this machine
brew bundle add --cask X --file=brew/Brewfile.common    #    or all machines
brew bundle install     # 4. install the rest

Two things that bite

Never run brew bundle dump at these paths. It rewrites the whole file and destroys the instance_eval lines. add appends and leaves them intact. Dump to a scratch path instead.

--no-upgrade is not optional. Without it, brew bundle counts outdated as unsatisfied: check reports installed-but-old packages as missing, and install turns into a mass brew upgrade of the whole machine. Upgrading is upd's job. 10-env.sh exports HOMEBREW_BUNDLE_NO_UPGRADE=1 for you, so this only matters in a shell that hasn't loaded profile.d.

Set up a machine

# new machine
git clone git@github.com:lambda-m/dotfiles.git ~/dotfiles
cd ~/dotfiles && ./bootstrap.sh          # then open a new shell

# machine that already has the repo but not dots yet
cd ~/dotfiles && git pull && ./bootstrap.sh

# from then on, everywhere
dots sync

bootstrap.sh creates the shared directories, repairs a folded ~/.local, removes an empty ~/.emacs.d, sets pull.rebase and push.autoSetupRemote, and stows core shell bash zsh tmux emacs, plus ghostty ccstatusline on macOS. Pass package names to stow only those.

If git pull refuses because of local edits, run git stash first and git stash drop afterwards. The usual culprit is a tool rewriting its own config file.

On a Mac, follow up with the brew survey in brew.

Packages: what is special in each

core

~/.profile is the shared entry point that sources profile.d and, in bash, .bashrc. Rarely touched.

shell

~/.local/profile.d (the table in How it fits together) and ~/.local/bin:

  • dots and upd: this manual.
  • ta [name]: tmux attach-or-create, default session main. Switches client when already inside tmux. Tab-completes session names.
  • mkcd DIR: mkdir and cd.
  • ytgrab: YouTube downloader with playlist symlinks. Bash, needs yt-dlp.
  • sshconfig-open HOST and SSHConfigOpener.app: open an ssh host in a new Ghostty window (macOS).

bash and zsh

Both are thin. Bash has ta completion. Zsh has the virtualenv-aware prompt, compinit with ~/.zsh/completion (a custom _make), ta completion, and bindkey -e so the line editor stays Emacs-style even when $EDITOR is vim. Both end by sourcing their .local file.

Both keep 50,000 lines of deduplicated history, and commands that start with a space aren't saved. When fzf is installed, they load its key bindings, using fzf --zsh or --bash (fzf 0.48 or later), else the distro's key-bindings file:

  • Ctrl+R fuzzy history: type to filter, arrows to move, Enter pastes onto the prompt without running it, Esc cancels, Ctrl+R again toggles time or relevance order. The picker shows the key hint.
  • Ctrl+T inserts a file path. Alt+C changes into a subdirectory.

tmux

~/.config/tmux/tmux.conf, plus a ~/.tmux.conf shim for old tmux. Nord theme, mouse on, 1-based indexes, splits on prefix | and prefix -. extended-keys on so Shift+Enter reaches Claude Code. Reload with tmux source-file ~/.config/tmux/tmux.conf. See the tmux wiki.

emacs

Config in ~/.config/emacs, all state in ~/.local/state/emacs (elpa, custom.el, caches). Runs as a daemon: emacs and emacs-cli are terminal clients, emacs-gui opens a frame. Packages come from MELPA through use-package: nord-theme, neotree, no-littering, xclip, and auto-package-update, which asks weekly in the first frame.

  • F8 neotree, M+arrows move between windows, Esc quits.
  • C-c y YAML to JSON, C-c j JSON to YAML. Needs yq.

After config changes, restart the daemon with emacsclient -e '(kill-emacs)', then open emacs.

ghostty (macOS)

Nord, IosevkaTerm Nerd Font 16, left Option as Alt, huge scrollback. Cmd+` toggles the quick terminal from anywhere. See the Ghostty config reference.

ccstatusline (macOS)

The Claude Code status line: model, session and weekly usage, context percentage, git branch and changes, Nord colors. Installed as a global npm package, so upd upgrade npm updates it. It rewrites its own settings.json on version bumps; when that shows up, run dots sync. For the interactive editor, run ccstatusline in a terminal. See ccstatusline on GitHub.

sublime

User settings only: the Package Control list, Markdown and MarkdownPreview, LSP-yaml, the Terminus color scheme. Stow it only on machines with Sublime Text, with ./bootstrap.sh sublime.

Not stowed

brew/ (see brew), wallpapers/ (old computer photos), README.md, this manual, and .stowrc, which targets $HOME and ignores .DS_Store.

Troubleshooting

SymptomCause and fix
Hundreds of MB untracked under shell/.local/share A bare stow shell folded ~/.local into a symlink. Run ./bootstrap.sh; it moves the foreign files to the real ~/.local and restows.
Emacs ignores the config A ~/.emacs.d or ~/.emacs exists and shadows ~/.config/emacs. bootstrap removes an empty one; otherwise move it away and restart the daemon.
Shift+Enter submits in Claude Code You're in a tmux started before the extended-keys setting. Detach and run ta again.
An installer appended lines to ~/.zshrc That edited the repo. Move the PATH line into 00-path.sh with path_append, delete it from the rc file, and run dots sync.
Everything works in zsh but nothing works in bash: no ta, no $EDITOR, missing PATH entries A ~/.bash_profile exists and shadows ~/.profile. Bash login shells read the first of .bash_profile, .bash_login, and .profile, then stop, so profile.d never loads. Installers create it. Move its lines into 00-path.sh and delete it. Check with env -i HOME="$HOME" bash -lc 'echo $EDITOR; type -t ta'.
dots sync says pull failed Rebase conflict. Run dots git status, fix the file, then dots git rebase --continue and dots sync. For ccstatusline's settings.json, take either side.
dot: can't open sync That's Graphviz. The helper is called dots.
brew bundle ignores this machine's file The hostname doesn't match a file, so HOMEBREW_BUNDLE_FILE is unset. Compare uname -n with the files in brew/, then rename one of them. See Which file this machine uses.
brew bundle cleanup wants to remove half the machine You passed Brewfile.common instead of a machine file. Common has no instance_eval, so cleanup never sees the machine-specific entries. Pass a machine file, or no --file at all.
brew bundle check lists things that are installed They're outdated, and plain check treats outdated as unsatisfied. Add --no-upgrade to ask only whether it's installed. Upgrading is upd's job.
brew bundle install started upgrading the whole machine Same cause, worse effect: without --no-upgrade it upgrades every outdated package, not only the missing ones. Set HOMEBREW_BUNDLE_NO_UPGRADE=1 in ~/.profile.local.
brew bundle fails en masse with an Xcode error One source-built formula needed a compiler and aborted the batch; everything after it reports "failed" without being touched. Check xcode-select -p against the macOS version. Casks and bottles don't need Xcode, so rerun with --no-upgrade.
A cask is registered under an old, renamed token Both tokens claim the same app, so brew uninstall --cask OLD would delete it. Remove only brew's record: rm -rf /opt/homebrew/Caskroom/OLD_TOKEN.
A machine Brewfile lost its instance_eval lines Something ran brew bundle dump at that path, and dump rewrites the whole file. Restore from git and use brew bundle add instead, which appends.
A cask installs but check still reports it missing Its app was installed by hand at a different version, so --adopt refused. Replace it with brew install --cask --force NAME, which upgrades to the cask's version.
Login shows no updates: line although things are outdated The cache is older than a day and a refresh is running in the background. Open the next shell, or run upd check.
